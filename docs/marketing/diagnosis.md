# Homepage Diagnosis and Story Map

## Diagnosis

The replaced page assembled many individually plausible marketing sections but repeated the same centered heading, paragraph, and contained preview pattern. Several product previews hard-coded contradictory sample numbers, dates, revenue deltas, and a fictitious `mytrackyo.local` browser frame. The smallest body labels made the interface look illustrative rather than like evidence. The old solutions/trust/price copy also included unsupported check-in speed, GST-compliance, ID-document, cash-drawer, permanent-free and no-commission claims.

The redesign changes the page's composition and story rather than reskinning the repeated section template. The existing reception image was not used: its provenance is unknown, it contains no visible operator, and its signage looks synthetic. The morning sequence is explicitly labelled illustrative instead.

The visual baseline was inspected in the live local browser after implementation at the available desktop and mobile viewport sizes. A before-image set and Lighthouse trace were not captured before editing, so no before/after performance or screenshot comparison is claimed.

## Information Architecture

| Section | Visitor question | Proof / composition |
| --- | --- | --- |
| Hero | What is MyTrackYo? | Concrete operator headline beside a readable Today scene and direct actions. |
| Morning moment | Do you understand my day? | Ink timeline of illustrative front-desk decisions; promoted “five notebooks” line. |
| Today | What needs attention? | Derived arrivals, departures, in-house count, and balance due. |
| Bookings | Can I find a stay quickly? | Keyboard-operable sample search with linked booking detail. |
| Calendar | Which room is free? | Labelled, horizontally scrollable room-by-night board. |
| Payments | What is paid and owed? | Folio arithmetic from the same fixture. |
| Portfolio | Can I see more than one property? | Property switcher and roll-up table from shared sample records. |
| Use cases | Is this for my kind of place? | Expandable editorial list, not a grid of cards. |
| Why it exists | What is the product's point of view? | Typography-led operator promise without pricing claims. |
| Trust ledger | What does it not do? | Verified current capabilities beside clear limitations. |
| FAQ | What are the practical boundaries? | Native details disclosures with factual answers. |
| Final CTA | What should I do next? | Distinct closing statement, signup and safe sample-workspace action. |
